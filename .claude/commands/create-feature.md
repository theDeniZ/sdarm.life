# Create Feature Request

Reference template: [@.github/ISSUE_TEMPLATE/feature_request.yml](.github/ISSUE_TEMPLATE/feature_request.yml)

Create a new feature request issue on GitHub. Follow the template structure and gather the following information:

1. **User story** — Frame the request in user story format:
   - "As a [user], I want [feature], in order to [benefit], unlike today when [current state]"
   - Example: "As a songbook user, I want to search by lyrics, in order to find songs I don't know the title for, unlike today when I can only search by title or number"

2. **Description** — Additional context and details:
   - How it should work
   - Expected flow or outcome
   - Acceptance criteria (optional, as checklist)
   - Screenshots, design ideas, or links to similar features

3. **Which app?** (optional) — Select from:
   - All apps
   - Web (sdarm.life)
   - Admin (admin.sdarm.life)
   - Songbook (songs.sdarm.life)
   - Treasures (treasures.sdarm.life)
   - Events (events.sdarm.life)
   - API (api.sdarm.life)

After gathering this information, use the GitHub MCP tool to create the issue with:
- **Title** — a concise title derived from the user story
- **Body** formatted with:
  - User story
  - Description and details
  - App context
- **Label** `enhancement` (auto-applied)
- **Repository** `theDeniZ/sdarm.life`

Ensure required fields (user story and description) are filled before creating the issue.
